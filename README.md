# ТелеСтена — Telegram-бот для дизайнеров интерфьера

Бот принимает **молды** (рендеры помещений без текстур), **текстуры** и **референсы**, бриф
текстом или голосом, а через LLM структурирует запрос, генерирует N вариантов, выбирает лучший
и присылает его. Следующий запрос работает поверх лучшего результата: шаги цепочки хранятся,
к любому шагу можно откатиться.

Стек: Python 3.12, aiogram 3.x, httpx, Pydantic v2, aiosqlite, Pillow, NumPy, scikit-image (SSIM),
STT через OpenRouter (или локальный faster-whisper). Без LangChain/Celery/Redis/ORM — только
асинхронность и SQLite.
Подробности решения и расхождения с ТЗ — в [NOTES.md](NOTES.md).

## Возможности

- Роль файла (молд/текстура/референс) определяет LLM по картинке; обычная подпись вроде
  «дуб тёмный» подаётся ей как подсказка. Разметка ролей (`текстура: …`) не требуется.
- Альбомы собираются в одну пачку, файлы дедуплицируются по sha256.
- Бриф → строгий JSON-план через tool use (Pydantic + один repair-retry); бриф можно писать
  свободно, без формата «поверхность → текстура» — планировщик сам сопоставляет материалы;
  при реальной неоднозначности — один уточняющий вопрос.
- Перед планированием — фаза просмотра: по каждому **новому** изображению в чат падает
  блок-цитата «🖼 Смотрю…» и стримингом дописывается описание, затем отдельный блок
  «🧭 Как применю материалы» со стримингом рассуждений. Описания кэшируются в БД
  (`files.analysis`) и кормятся оркестратору; просмотренные файлы повторно не смотрятся.
- Генерация через K3 Edit (Image API), варианты параллельно с ретраями; судья-LLM оценивает
  кандидатов **по реальным изображениям** (молд + текстуры + кандидат — vision, не описания)
  по рубрике + программный SSIM по границам; при низком качестве — автоматическая перегенерация.
- **Все изображения уходят документами** (Telegram сильно пережимает `send_photo`):
  победитель — первый, с кнопками «Ещё варианты», «Откатить», «Продолжить от этого»;
  остальные варианты шага присылаются **автоматически сразу за ним** с номерами (№1 — победитель).
- Отправка в один этап: подпись на фото/альбоме = бриф, пайплайн стартует сразу (картинки
  прикреплены к сообщению — планировщик предпочитает их как базу для правки).
- Загрузка без брифа даёт «инструментальные» блоки вместо ✅-строк: «🔧 Шаг #N · смотрю
  изображение» + стриминг рассуждений (модель сама называет картинки; пользовательские
  подписи-промпты не сохраняются как названия — `_clean_caption` оставляет только роль
  или короткую подсказку ≤40 символов).
- Бриф текстом/голосом **без картинки** — бот сначала шлёт галерею **сгенерированных
  вариантов** активного шага (текущий результат → альтернативы по скору; если генерации
  ещё не было — загрузки, названные моделью) документами с кнопками «Править №…»;
  тап = правка выбранного по исходному брифу (выбор живёт 10 минут).
- Постоянные инструкции (`/instructs`) текстом или голосом, подмешиваются в системный промпт.
- Стриминг текста через live-драфты `sendMessageDraft` (с фолбэком на send/edit), троттлинг и
  учёт FLOOD_WAIT; конвертер Markdown → Telegram HTML; чистка служебных артефактов (`clean_output`).
- Whitelist по `ALLOWED_USER_IDS`, лимит картинок в день, `/selfcheck`, корректное завершение.

## Быстрый старт

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполни BOT_TOKEN, OPENROUTER_API_KEY, ALLOWED_USER_IDS
python -m bot.main        # long polling
```

Проверь здоровье: отправь боту `/selfcheck` — получишь список ✅/⚠️/❌ (токен, ключ OpenRouter,
доступность моделей, БД, ffmpeg, STT, поддержка `sendMessageDraft`).

### Docker

```bash
cp .env.example .env   # заполни значения
docker compose up -d --build
docker compose logs -f
```

Данные (SQLite + файлы) лежат в `./data` (volume в `DATA_DIR=/app/data`), в образе есть `ffmpeg`.

## Конфигурация (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота от @BotFather | — |
| `OPENROUTER_API_KEY` | ключ OpenRouter | — |
| `ALLOWED_USER_IDS` | whitelist через запятую | пусто |
| `LLM_MODEL` | оркестратор/судья/vision | `anthropic/claude-haiku-5.5` |
| `IMAGE_MODEL` | генерация изображений | `krea/k3-edit` |
| `IMAGE_RESOLUTION` | разрешение генерации: `1K` / `2K` (фолбэк на `1K`) | `2K` |
| `DEFAULT_VARIANTS` / `MAX_VARIANTS` | число вариантов | `4` / `8` |
| `DAILY_IMAGE_LIMIT` | лимит картинок в день на пользователя | `60` |
| `STT_PROVIDER` | `cloud` (OpenRouter) или `local` (faster-whisper, нужен ffmpeg) | `cloud` |
| `STT_MODEL` | облачная STT-модель | `mistralai/voxtral-small-transcribe-3-0` |
| `WHISPER_MODEL_SIZE` | локальная модель whisper | `small` |
| `MAX_VOICE_SECONDS` | лимит длительности голосового | `120` |
| `DATA_DIR` | каталог данных | `data` |

## Работа с ботом

1. `/start` — справка.
2. Пришли картинки **сразу с брифом в подписи** — одним сообщением, без всякой разметки
   (роли определяются LLM). Или двумя: сначала картинки (бот ответит блоками «Шаг #N ·
   смотрю изображение» с рассуждениями), потом бриф — тогда покажет галерею вариантов
   и попросит тапнуть номер.
3. Бриф пишется свободно: «сделай скандинавский стиль, пол светлый дуб, 4 варианта».
   Уточняющий вопрос — только если задача действительно непонятна. Правка с прикреплённой
   картинкой идёт по ней; отредактировал сообщение в чате — бот отвечает заново.
4. Бот пришлёт все результаты документами (без пережатия): победитель — первый с кнопками
   «Ещё варианты», «Откатить», «Продолжить от этого», остальные — сразу за ним с номерами.
5. `/history` — шаги с миниатюрами и откатом к любому шагу; `/new` — новый проект;
   `/files` — просмотр и удаление файлов; `/settings` — варианты/формат; `/instructs` —
   постоянные инструкции; `/cancel` — отмена текущей генерации.

## Деплой на Render

Бот работает через long-polling и не слушает HTTP, но Render-веб-сервис обязан
занять `$PORT` и отвечать на health check. Для этого в том же процессе поднимается
**сервисная заглушка** `bot/webstub.py` (aiohttp): маршруты `/`, `/health`,
`/healthz` → `200 {"status": "ok", ...}`. Порт берётся из переменной окружения
`PORT` (Render назначает её сам), локальный дефолт — `HTTP`-`port=8080`.

В корне лежит `render.yaml` (Blueprint):

- web-сервис на Docker (`Dockerfile`), `healthCheckPath: /health`;
- д��ск 1 GB смонтирован в `/app/data` — SQLite и картинки переживают деплои;
- `STT_PROVIDER=cloud` (локальному whisper на free-плане не хватит памяти);
- секреты `BOT_TOKEN`, `OPENROUTER_API_KEY`, `ALLOWED_USER_IDS` задаются в
  дашборде Render (`sync: false`).

Настройка: New → Blueprint → выбрать репозиторий → задать три секрета → Deploy.

> Free-план засыпает после ~15 минут простоя. Чтобы бот не засыпал,
> поставь внешний пингер (UptimeRobot и т.п.) на
> `https://<service>.onrender.com/health` с интервалом ≤10 минут — заглушка
> отвечает мгновенно, а бот продолжает поллинг в том же процессе.

## Архитектура

```
bot/
  main.py            # запуск, middleware whitelist, роутеры, graceful shutdown
  config.py          # pydantic-settings
  handlers/          # start/help, instructs (FSM), files, history, settings, selfcheck, messages
  llm/               # openrouter.py (клиент), orchestrator.py, judge.py, prompts.py, schemas.py
  imaging/           # generate.py (K3 Edit), metrics.py (SSIM по границам Canny)
  stt/               # base.py, whisper_local.py (faster-whisper), cloud.py (OpenRouter STT)
  telegram/          # draft_streamer.py, formatting.py (md→html, clean_output), albums.py
  db/                # schema.sql, repo.py (aiosqlite, WAL, foreign keys)
  services/          # pipeline.py (цепочка шагов), files.py, role.py, userqueue.py, selfcheck.py
tests/
```
